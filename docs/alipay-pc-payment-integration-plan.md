# 支付宝电脑网站支付完整接入计划

## 摘要

按支付宝“自研商家”模式完成电脑网站支付接入，并补齐应用网关、交易查询和超时处理、管理员退款/关单、账单下载及上线验收。现有页面支付请求和支付通知回调已实现，但支付宝指南要求的应用网关、主动查询与对账等尚未完成；当前购买开关保持关闭。

计划依据：[自研商家接入准备](https://ideservice.alipay.com/cms/site/0izbjp)、[电脑网站支付接口](https://ideservice.alipay.com/cms/site/0izblh)、[电脑网站支付流程](https://ideservice.alipay.com/cms/site/0izbjt)。

## 实施内容

### 1. 支付宝平台设置与应用网关

- 按自研商家模式配置网页/移动应用，启用 RSA2 公钥模式，绑定商家账号，申请并开通电脑网站支付产品，提交应用上线审核。
- 增加独立应用网关路由 `GET/POST /api/v1/alipay/app-gateway`。GET 提供 HTTPS 公网安全检测响应；POST 验签并分发已支持的通知。未知通知类型拒绝处理并记录最少必要元数据；未接入的其他支付宝产品不订阅、不启用。
- 电脑网站支付仍使用每笔请求的 `notify_url=https://d2s.site/api/v1/alipay/d2s/notify`；付款后的 `return_url=https://d2s.site/d2s` 只负责浏览器跳转，不作为付款依据。
- 后台超级管理员可设置支付宝前置二维码展示模式：`qr_pay_mode=0/1/3/4`。模式 4 使用服务端固定的 `qrcode_width`；本站将支付表单 POST 到支付宝收银台的隔离 iframe 中，用户留在本站页面扫码。二维码刷新由支付宝页面处理。若支付宝浏览器策略或控制台配置阻止 iframe，提供清晰错误提示和用户主动选择的支付宝新页面支付备用入口。

### 2. 支付查询、超时关单和回调恢复

- 实现 RSA2 签名的 `alipay.trade.query` 客户端，并验证支付宝 API 响应签名、应用 ID、订单号、金额、币种及卖家身份。
- 增加主节点定时对账：查询未完成的支付宝订单；确认成功时通过现有支付结算事务履约；等待付款时保持订单未支付；订单超时后调用 `alipay.trade.close`，只有支付宝确认关闭后才取消本站订单并释放预留余额；结果不确定时保留待处理并重试，不能误取消。
- 通知回调与主动查询共用幂等结算逻辑，保证并发或重复通知不重复发放授权、余额或邀请奖励。

### 3. 管理员退款、关单和账单

- 新增超级管理员专用退款接口，输入订单、退款金额、原因和幂等键；以支付宝实际收款金额为上限，记录每次退款号、状态、金额和操作审计。
- 支持多次部分退款，累计金额不得超过实付金额；退款 API 响应不明确时先查退款/交易状态，不能盲目重复退款。
- 部分退款后保持授权；累计全额退款确认成功后，停用相关授权并更新订单状态。
- 新增超级管理员关单操作，只允许处理未支付订单，并先查询再关单；新增按日期查询并下载支付宝交易账单的管理员功能。账单通过 HTTPS 获取并直接下载，不在本站长期保存。

### 4. 前台支付选择和配置文档

- 支付宝渠道保持首位、标准 Logo 和“推荐”标识；渠道可用时默认选中支付宝，用户可切换已开放渠道。
- 新增环境变量说明：应用 ID、卖家 ID、商户私钥、支付宝公钥、支付通知地址、付款返回地址和正式/沙箱网关。应用网关地址固定为 `https://d2s.site/api/v1/alipay/app-gateway`，在支付宝开放平台配置；密钥只经受限 Secret 注入。
- 更新 API 文档、运维配置、支付实施计划和上线清单。可选的服务器 IP 白名单仅在生产出口 IP 固定且支付宝支持时启用。

## 接口与数据变更

- 应用级通知入口：`GET/POST /api/v1/alipay/app-gateway`，与电脑网站支付的 `notify_url` 回调保持独立。
- 管理员新增：按订单发起退款、查询退款记录、关闭待付款订单、按日期下载账单；所有操作要求超级管理员角色并写入管理审计。
- 订单/支付事件增加累计退款金额、退款幂等号及结果状态，退款金额使用最小货币单位存储。
- 拒绝支付宝订单混用本站余额支付，避免部分退款时无法准确判断实付金额与授权撤销条件。

## 测试与验收

- 自动测试：请求及通知签名、应用网关 GET/POST、错误签名/应用/卖家/订单/金额、重复通知、查询成功/待付款/关闭/未知状态、通知与查询并发、过期关单、重复与部分退款、退款金额上限、全额退款后停用授权、权限拒绝及审计、账单日期与下载校验。
- 沙箱验收：创建订单、支付成功通知、通知丢失后主动查询、等待付款后关单、重复通知、部分及全额退款、账单下载；验证应用网关安全检测无跳转且公网 HTTPS 可访问。
- 生产门禁：完成支付宝应用审核和产品开通，注入正式密钥与 `D2S_ALIPAY_SELLER_ID`，执行小额支付、到账核对、退款和账单核对后，才开放 `D2S_PURCHASES_ENABLED` 与 `D2S_ALIPAY_PC_ENABLED`。

## 隔离真实支付验收环境

沙箱服务不可用时，真实小额验收应使用独立的验收部署，不能打开生产购买总开关。仓库提供：

- `deploy/d2s-alipay-acceptance.env.example`：独立数据库/Redis、容器名、数据目录、3001 回环端口和正式支付宝密钥占位模板。复制到服务器 Secret 管理后填值，严禁提交已填密钥的文件。
- `deploy/d2s-alipay-acceptance.nginx.conf.example`：验收子域名的 Nginx TLS 反代模板，指向 `127.0.0.1:3001`。
- 根 Compose 已支持独立项目名、容器名、绑定端口、数据目录及支付宝环境变量；生产默认值保持原样，验收购买开关只写入验收环境文件。

建议验收域名为 `alipay-acceptance.d2s.top`。部署前需在 DNS 添加指向源站的 A 记录，在源站签发该域名的 HTTPS 证书并启用 Nginx 模板。服务器需为该实例配置独立的 PostgreSQL 数据目录/卷、Redis、会话密钥、管理员和应用 Secret；业务库不得复用生产数据库。验收栈通过 Compose 独立项目名启动，并绑定回环端口，由 Nginx 提供公网 HTTPS。

支付环境使用生产支付宝 App ID、Seller ID、商户私钥和支付宝公钥，只注入验收容器。支付宝应用网关和每笔请求的 `notify_url` 都指向验收域名。应用网关为：

```text
https://alipay-acceptance.d2s.top/api/v1/alipay/app-gateway
```

电脑网站支付通知为：

```text
https://alipay-acceptance.d2s.top/api/v1/alipay/d2s/notify
```

验收数据库只保存测试账户和测试订单；测试邮件服务需能完成邮箱验证。使用商家控制的付款账号，单笔不超过负责人批准的上限；支付成功后立即执行全额退款，随后核对支付宝退款记录及对应日期账单。不要开放正式站点的购买总开关。

**当前进度**：本地已补充隔离部署模板和 Compose 参数；尚未在服务器创建 DNS、证书、验收容器或独立数据库。生产两个域名的应用网关路径仍需先解决 404/部署问题，不代表验收栈已上线。

## 实施状态（本地代码）

- 已落地：独立应用网关 GET/POST、电脑网站支付前置二维码 iframe、超级管理员二维码模式设置、验签主动查询、主节点定时对账、确认后关单、退款记录与幂等额度控制、管理员退款/退款查询/关单/账单页面和后台审计。
- 订单全额退款才停用授权；部分退款保留授权。支付宝订单不会由通用超时任务自动取消，外部结果不确定时保留待核。
- 仍需在支付宝开放平台配置应用网关并开通电脑网站支付，注入商户生产或沙箱密钥，再完成真实沙箱验证。生产购买开关继续保持关闭，直到沙箱和生产等价环境的支付、回调、查询、退款及账单验收完成。

## 默认假设

- 接入身份为商家自研应用，不使用服务商代开发或 `app_auth_token`。
- 采用支付宝 RSA2 公钥模式；如商家控制台要求证书模式，需将证书轮换与验签支持纳入实施。
- 退款、关单和账单仅对超级管理员开放，用户不自助退款。
- 未启用其他需要应用网关的支付宝产品；后续新增产品时必须先实现对应通知解析和处理，再启用订阅。
- 最终生产应用审核、产品开通和密钥注入需在支付宝控制台及服务器 Secret 配置中完成。
