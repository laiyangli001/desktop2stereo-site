# 网站安全管理制度

**文件编号**：SEC-001

**版本**：V3.2（2026-11-03 复核）

**生效日期**：［签署后填写］

**编制**：［安全管理负责人姓名］

**批准**：［法定代表人或主要负责人姓名］

**适用网站**：d2s.site

**适用系统**：Desktop2Stereo 网站、账户与邮箱验证服务、订单和支付接口、软件授权与设备管理接口、后台管理程序及其数据库和运维环境

> 本制度用于规定 d2s.site 的安全管理要求。制度中的强制控制条款代表运营要求；代码仓库中的功能、生产环境实际启用状态和验收状态以第十章“实施状态与生效前核对表”为准。未完成核对的控制不得对外宣称已在生产环境落实。

## 第一章 总则

**第一条** 为规范本网站账户、交易、软件授权和后台管理安全，保护用户信息，建立日志留存、应急处置和监管配合机制，依据实际适用的法律法规及主管部门要求制定本制度。法律法规发生变化时，安全管理负责人应组织复核。本制度依据范围包括《中华人民共和国网络安全法》（2025 年 10 月修正、2026 年 1 月 1 日起施行的文本）、《中华人民共和国个人信息保护法》《中华人民共和国数据安全法》《中华人民共和国计算机信息系统安全保护条例》《计算机信息网络国际联网安全保护管理办法》《互联网安全保护技术措施规定》，以及在实际经营活动适用时的《中华人民共和国电子商务法》。具体适用义务取决于运营主体、网络设施位置、服务对象及数据处理活动；《个人信息保护法》也规定了境外处理境内自然人个人信息、并以向境内自然人提供产品或服务为目的等情形的适用范围。网站面向全球用户不当然排除中国或其他国家和地区的强制规定，签署前应完成适用性核对。

**第二条** 本网站向全球用户提供 Desktop2Stereo 软件介绍、购买、下载入口及使用说明；通过电子邮箱账户管理订单、付款状态、软件授权、设备绑定和登录凭据。服务端代码还包含支付回调、余额、邀请奖励及提现审核等业务能力；具体渠道和功能仅在运营方实际启用后适用。

**第三条** 本网站不提供用户向公众发布文字、图片、音视频等内容的功能，不提供用户之间的评论、即时通讯或群组功能。因此，不设置针对用户公开内容的审核岗位或内容传播监控流程。若将来新增公开发布、评论、通讯或社区功能，须先评估并修订本制度及相应技术控制。

**第四条** 本制度适用于账户注册、邮箱验证、登录退出、密码重置、订单和支付、软件下载与授权、设备管理、后台操作、日志保存、个人信息保护、投诉处理、应急响应及监管配合。

**第五条** 本制度须由责任人审核、批准并签署后生效。网站实际功能或适用要求变化时，安全管理负责人应提出修订并留存版本记录。制度文本不得替代系统实际控制、必要的备案许可或主管部门要求。

## 第二章 安全责任与后台权限

**第六条** 安全管理负责人任命已完成（据网站负责人确认）；负责人姓名及任命文件按已签署文件填写并归档。安全管理员由负责人指定并留存指定书。人员变更时应更新任命文件、权限和交接记录。

**第七条** 安全管理负责人负责统筹本制度执行、批准监管数据调取与导出、决定异常账户处置、组织应急响应、对接主管部门，并复核安全事件和制度执行情况。

**第八条** 安全管理员按授权执行账户和订单核查、日志查询与导出、紧急账户限制、投诉记录和材料归档。安全管理员不得共享管理员凭据，不得超出审批范围查看、导出或修改数据；日志不得由管理员修改或删除。

**第九条** 后台管理员身份与前台用户账户分离。前台账户不得直接用于后台登录。后台登录使用独立管理员凭据、强密码和失败锁定；超级管理员初始化通过受控部署流程完成，不开放公开注册。

**第十条** 后台页面和管理 API 默认要求管理员身份认证。日志查看/导出、账户限制、权限管理和留存清理按最小权限分配角色。后台敏感读写操作均须记录操作者、时间、来源 IP、目标对象和执行结果。账号应使用个人专属凭据；具备条件时启用多因素验证。

## 第三章 账户、邮箱和个人信息管理

**第十一条** 用户以电子邮箱注册。账户完成邮箱验证码验证后方可激活；未验证账户不得登录、购买、创建有效授权或取得下载授权。验证码有效期不得超过 15 分钟；发送接口须按邮箱和来源 IP 限速，并使用已启用的反自动化措施。

**第十二条** 系统记录注册时的邮箱、注册时间、来源 IP 和 User-Agent，并保留邮箱验证状态及验证时间。用户完成邮箱验证码后，账户激活状态、注册快照及成功的 `REGISTER` 行为日志须在同一数据库事务中写入；任一写入失败则整体回滚，避免账户激活但缺少对应留痕。注册快照与账户后续修改的邮箱分开保存；如邮箱变更功能开放，应另行记录变更事件，不得改写注册时快照。

**第十三条** 本网站当前仅以邮箱验证码确认用户对该邮箱的控制权；邮箱验证不等于真实身份核验，也不得在自评估或对外说明中表述为实名。后台证件核验页面和 API 已停用，当前不采集证件号码、证件影像或身份核验结论。网站实际提供软件介绍、在线购买和软件下载服务，虽不提供用户公开信息发布、评论、即时通讯或群组功能，但这本身不足以排除真实身份核验义务。负责人于 2026-11-03 报告运营主体所在地为山东省烟台市、网站只销售自有 Desktop2Stereo 软件且不接受第三方或用户上架；其将 ICP 备案/许可类别描述为“软件开发”，但登记主体及备案/许可材料尚未核验，安装包由本站托管还是仅提供外部下载链接也待确认。现行[《网络安全法》第二十六条](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)及[《互联网用户账号信息管理规定》第九条](https://www.cac.gov.cn/2022-06/26/c_1657868775042841.htm)针对列明的网络接入、域名注册、电话入网、信息发布和即时通讯等功能规定身份要求；另有现行[《反电信网络诈骗法》第二十一条第（四）项](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_d30139b442a141f48f05775d8c0b3cee.html)明确列出“信息、软件发布服务”及“网络交易”服务，并规定相关服务提供者在与用户签订协议或确认提供服务时要求用户提供真实身份信息。根据本网站的软件销售、支付和下载模式，本条是否适用于本站以及覆盖哪些用户/环节，尚无经核实的运营主体与业务分类结论；这是待解决的合规风险，不能仅以无 UGC、无群组或只有邮箱注册作出豁免判断。须在提交自评估前，由负责人取得主管部门或合格法律顾问基于运营主体、许可/备案类别、软件销售与分发模式及用户角色作出的书面适用性意见。确认前不得宣称“邮箱已完成实名”“确定无需实名”或本条当然适用；也不得为迎合法规猜测而先行收集证件。若确认需核验，应先确认适用于境外用户的合法核验方式、个人信息处理依据、最少必要字段、告知、访问权限、安全措施和保存期限，再实施相应服务门禁。2026 年公开征求意见的[《互联网信息服务管理办法（修订草案）》](https://www.cac.gov.cn/2026-07/03/c_1784822399677167.htm)仍为征求意见稿，不作为现行义务依据。

**第十四条** 个人信息按提供账户、购买、支付、下载和授权服务所必需的范围处理。当前涉及的信息可能包括邮箱、账户标识、注册/登录/购买来源 IP、User-Agent、订单及支付渠道返回的有限关联标识、软件授权和设备摘要。设备指纹、来源端口、服务目标地址或支付账户标识无法从运行环境或渠道可靠取得时，字段保留空值，不得伪造。

**第十五条** 支付账户标识仅保存渠道实际返回且业务确有必要的脱敏值或摘要；不保存完整银行卡号、支付密码、验证码或支付凭证明文。任何第三方支付渠道是否提供可追溯标识，以渠道接口和实际配置为准。

**第十六条** 管理员不得将用户资料、日志、订单或工单信息用于本制度目的以外的用途。向外提供数据须经过负责人审批并核对请求主体、法律依据、数据范围和交付方式；应保留审批及交付记录。

## 第四章 用户行为日志与留存

**第十七条** 系统应记录可识别的用户安全及业务行为，包括注册、登录成功与失败、退出、购买、密码重置、账户资料变更、授权相关操作及可识别账户的软件下载行为。每条行为日志至少包括：用户 ID、事件时邮箱快照、操作类型、UTC 事件时间（秒级）、来源 IP/端口、目标 IP/端口、User-Agent、设备指纹哈希、请求路径、结果状态和记录哈希。无法获得的网络字段或设备标识留空；未知账户的失败登录允许 user_id 为空。

**第十八条** 日志不得记录密码、邮箱验证码、访问令牌、刷新令牌、支付密钥、完整支付/Checkout 链接或 URL 查询参数中的敏感值。常规应用诊断日志不得输出用户邮箱明文；用户行为审计仅按规定字段和访问控制留存邮箱快照。User-Agent 和请求路径按规格限制长度并清理敏感参数。登录成功、失败和被安全规则拒绝的结果均须记录；连续失败达到系统阈值时应实施临时锁定或加强验证，并记录锁定/拒绝事件。

**第十九条** 用户行为日志、注册快照、后台操作审计及清理审计默认不自动删除。结合《中华人民共和国网络安全法》第二十三条第三项对相关网络日志不少于六个月的要求，并作为本网站的内部安全留存标准，系统对用户行为日志、注册快照和后台操作审计均设置不少于 366 天的硬编码清理下限，覆盖最长的 366 日历日年度，清理接口拒绝任何更短期限；日志代码中仍保留六个月法定基线的保护逻辑。该 366 天期限是对上述指定安全审计记录的内部策略，不自动扩展到工单正文、支付凭据或其他与安全审计目的无关的数据。每类个人信息仍须按实现处理目的所必要的最短时间处理并向用户如实告知；依法必须留存的个人信息，在期限届满前限制处理范围，期限届满后依法处置。依法应删除、更正或限制处理的请求，按适用法律评估并执行。不得仅凭本制度推定所有业务数据均属于法定网络日志。

**第二十条** 日志采取仅追加写入。后台和普通用户接口不得提供日志 UPDATE、DELETE、清空或删除表的功能。每条用户行为日志按固定版本的关键字段计算 SHA-256，并提供按日志 ID 重新计算和比对的校验功能。哈希校验用于发现记录变化，不单独构成对数据库管理员或底层存储的防篡改证明；应结合数据库权限、备份和运维审计。

**第二十一条** PostgreSQL/MySQL 生产数据库须为应用运行身份对用户行为日志、注册快照、管理员审计和清理审计表仅授予 INSERT 和 SELECT 权限，不授予 UPDATE、DELETE、TRUNCATE 或列级 UPDATE。审计表建表和升级须使用独立迁移身份，通过目标与 `D2S_APP_SQL_DSN` 相同数据库和 schema 的 `D2S_AUDIT_MIGRATION_DSN` 执行；迁移身份不得注入长期运行的应用服务。受控清理另使用独立身份。仓库提供 PostgreSQL/MySQL 权限脚本；Docker PostgreSQL 发布在切换应用前通过临时 maintenance 容器准备 `d2s_app`、`d2s_migrator`、`d2s_audit_cleanup` 角色，将普通业务表归属应用角色，迁移审计表并检查有效权限，任何步骤失败均停止切换。`d2s_app` 只可对审计表 SELECT/INSERT；清理身份仅对三张留存数据表 SELECT/DELETE，对清理审计表 SELECT/INSERT。PostgreSQL 权限检查还断言无列级 UPDATE、TRUNCATE、REFERENCES 和 TRIGGER。MySQL 权限可由全局、数据库、表及角色授权叠加，执行人须检查 `SHOW GRANTS` 和有效角色，确保不存在可覆盖表级限制的宽泛授权。SQLite 无法提供表级账户权限，须通过文件访问权限和独立维护流程补足，并如实记录该限制，不得声称已实现数据库账户级授权。2026-11-03 生产核验确认四张审计表由 `d2s_migrator` 所有；应用账号对审计表权限为 SELECT/INSERT、无 UPDATE/DELETE，清理账号对三张留存数据表仅有 SELECT/DELETE、对清理审计表仅有 SELECT/INSERT。该核验不替代日常权限复核和数据库备份。

**第二十二条** 受控清理仅允许删除已超过 366 天下限的数据。成功清理须在同一事务中写入清理审计记录并删除目标数据，记录至少包含执行人/任务身份、执行时间、各数据表独立的截止时间和起止范围、逐表删除数量及执行结果；用户行为日志、注册快照和后台操作审计的截止时间均不得早于当前 UTC 时间减去请求的至少 366 天；任一步失败均须回滚清理事务，并在新事务中追加 `FAILURE` 清理审计，记录失败阶段、逐表时间范围、实际删除数量（回滚时为 0）和候选记录统计数。清理审计本身不得被同一清理任务删除。当前实现已按该流程记录事务失败；若数据库故障同时阻断失败审计写入，后台还会尝试追加管理员操作失败审计，但数据库不可用时不能保证数据库内存在失败记录。生产启用前仍须验证迁移后的审计表结构、清理账号权限及故障恢复行为。

**第二十三条** 应按时间范围、用户 ID、邮箱、来源 IP 和操作类型查询日志，结果分页展示，授权角色不得隐藏本制度规定的字段。CSV 导出应包含用户行为日志全部字段，使用 UTF-8 编码，并采用 `access_log_YYYYMMDD_HHMMSS.csv` 文件名。注册信息导出至少包括邮箱、注册 IP、注册时间、邮箱验证状态和验证时间。日志、注册、购买记录的查询、哈希校验及导出须按后台审计策略记录操作者、筛选范围、时间和结果。导出须经安全管理负责人事前批准，审批凭证应与导出审计记录关联归档。后台已实现按用途和精确筛选范围绑定的双人审批，申请 30 分钟后失效且只可使用一次；申请人不得审批自己的申请，申请、决定、使用和导出均记录审计。生产使用前仍须配置至少两名不同的超级管理员并完成审批闭环验收。

**第二十四条** 登录用户通过首页 GitHub Release、夸克网盘或百度网盘入口发起下载时，客户端先调用服务端白名单跟踪路由。服务端校验用户会话、邮箱验证状态及登录限制，并在跳转前追加 `DOWNLOAD` 行为日志；目标值仅允许 `release`、`quark`、`baidu`。日志成功表示下载链接点击已记录，不代表外部文件传输完成。匿名用户仍可使用公开下载直链，该路径不关联账户。当前浏览器/服务端契约无法提供设备指纹时字段留空。

## 第五章 订单、支付和授权关联

**第二十五条** 购买记录须能关联订单编号、用户 ID、邮箱快照、购买时间、产品标识、金额、币种、支付方式、渠道可提供的脱敏/哈希支付账户标识、来源 IP 和结果状态。订单创建时保存的邮箱快照用于同一订单后续 Checkout 和重试；用户之后修改账户邮箱，不得改写订单快照或改变同一订单的支付请求身份参数。金额使用货币最小单位及明确币种保存。订单价格、支付成功状态和授权状态由服务端或已验证的支付回调确定，不信任客户端自行提交的价格或付款结果。

**第二十六条** 支付回调须验证相应支付渠道的原生签名或可信中转签名，并执行幂等处理。订单、支付事件和授权变更应保持可追溯关联。支付渠道未返回账户标识时保留空值，不得阻断合法支付或编造关联信息。

**第二十七条** 账户购买限制、邮箱未验证、订单状态异常或授权安全规则命中时，服务端须拒绝相应购买或授权操作。适用时记录订单/授权操作结果和阻断原因；不得只在前端隐藏购买入口。

**第二十八条** 设备标识仅保存摘要，不保存原始设备指纹。授权签名私钥、支付桥密钥、会话密钥等秘密不得进入制度附件、普通日志、代码仓库或用户可访问数据。

## 第六章 应急处置与账户紧急限制

**第二十九条** 出现批量异常注册、集中登录失败、异常购买/支付、账号被盗、授权滥用、数据泄露或服务受到攻击等情况时，安全管理负责人组织核查和应急处置；必要时由安全管理员协助。

**第三十条** 后台应支持针对单个账户立即禁止登录、禁止购买及撤销现有会话。限制必须在服务端所有相应入口生效，并记录管理员、账户、操作类型、原因、时间、来源 IP 和结果。解除限制使用对应的紧急解除操作并记录审计。

**第三十一条** 对按 IP 段、邮箱域名或注册时间窗口筛选的账户，可执行批量限制。执行前须展示筛选条件与预计影响账户数，进行二次确认；审计记录须保存操作参数、影响数量、操作者和结果。批量处置不得把筛选条件直接当作授权依据，执行人须复核目标范围。

**第三十二条** 应急处置时保全相关日志、订单、支付事件和授权状态，不得覆盖或删除证据。依法需向主管部门报告或提供资料时，由安全管理负责人按适用程序办理，并保留报送、查询和交付记录。事后形成处置时间线、影响范围、恢复措施和改进事项。

**第三十三条** 至少每年进行一次内部应急流程检验，覆盖账户限制、强制下线、日志查询和导出，并记录演练范围、结果、缺陷和整改情况。未验证的演练项目不得记为通过。

## 第七章 投诉与争议处理

**第三十四条** 网站在 d2s.site 页面右侧提供“投诉与咨询”浮动入口，用户可进入 `/support` 提交付款未到账、订单/授权、下载、软件使用、账户及其他问题或建议。联系面板同时提供运营方企业微信客服链接 `https://work.weixin.qq.com/ca/cawcde40faa1d08998`，供用户添加客服即时沟通。企业微信沟通由企业微信承接；只有站内表单留言会形成网站后台工单。该客服入口用于商业服务问题，不代表公安机关或监管部门入口；涉及违法和不良信息的举报渠道按主管部门公布的官方方式另行提供。

**第三十五条** 站内工单记录工单编号、必填账户 ID、问题分类、联系邮箱、用户自愿提供的订单号、标题和描述、提交时间、来源 IP、User-Agent、处理状态、面向用户的管理员回复及处理管理员。站内留言表单和提交 API 均要求用户先注册并登录；访客不能创建工单，不要求中国手机号或身份证。登录用户可在“我的工单”查看自己提交的记录。后台列表和更新仅限独立后台授权角色，查看与处理动作均写入管理员操作审计。用户工单列表由服务端按当前会话账户 ID 筛选，仅返回状态与面向用户的 `admin_reply`，不返回 IP、User-Agent、联系邮箱或经办管理员身份；当前未实现独立内部备注字段。页面应提示不得提交密码、验证码或完整支付卡信息。后台回复不会由系统自动发送邮件；客服通过企业微信或运营方实际配置的外部联系方式进行沟通。企业微信记录不与站内工单数据自动合并。工单不属于行为日志或注册审计表；不设置后台一键清除，不以 366 天日志策略作为工单无限期保存依据。运营方应根据争议处理目的确定保存期限，处理目的完成后按适用法律评估删除或匿名化，并同步更新隐私告知。

## 第八章 监管配合与数据支持

**第三十六条** 安全管理负责人负责接收依法提出的查询、调取和检查要求，核验主体和范围，审批数据查询或导出；安全管理员按审批执行并复核交付内容。提供数据应限定于合法、明确的范围，并记录依据、字段范围、导出人、复核人、时间、方式和结果。

**第三十七条** 监管数据优先使用可读、可核对的通用格式导出。导出文件应安全传递、限制访问，并按要求归档或在目的完成后依批准流程处置。不得通过未授权渠道发送账户密码、验证秘密或支付凭据。

## 第九章 安全运行与复核

**第三十八条** 正式域名为 `d2s.site`。生产环境应使用 HTTPS；反向代理仅信任明确配置的代理地址传入的客户端 IP。数据库、Redis 和内部管理端口不得因便于排障而直接暴露公网。生产配置、证书、备份、访问控制和恢复流程应按部署方案落实并定期复核。

**第三十九条** 生产数据应按运维方案备份并限制备份访问。审计数据备份应与在线业务数据分开控制，定期验证可读性和完整性。访问密钥、签名私钥和支付密钥通过受控 Secret 管理并制定轮换和泄露应急流程。

**第四十条** 安全管理负责人至少每年复核一次网站功能、日志字段、权限、留存、外部渠道和应急流程；出现重大功能变更、安全事件或适用要求变化时应及时复核。本制度的任何条款均不得被解释为系统已经通过尚未执行的部署验收或合规评估。
