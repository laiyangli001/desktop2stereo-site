# 网站安全管理制度

**文件编号**：SEC-001

**版本**：V1.8（2026-11-02 复核）

**生效日期**：［签署后填写］

**编制**：［安全管理负责人姓名］

**批准**：［法定代表人或主要负责人姓名］

**适用网站**：d2s.site

**适用系统**：Desktop2Stereo 网站、账户与邮箱验证服务、订单和支付接口、软件授权与设备管理接口、后台管理程序及其数据库和运维环境

> 本制度用于规定 d2s.site 的安全管理要求。制度中的强制控制条款代表运营要求；代码仓库中的功能、生产环境实际启用状态和验收状态以第十章“实施状态与生效前核对表”为准。未完成核对的控制不得对外宣称已在生产环境落实。

## 第一章 总则

**第一条** 为规范本网站账户、交易、软件授权和后台管理安全，保护用户信息，建立日志留存、应急处置和监管配合机制，依据实际适用的法律法规及主管部门要求制定本制度。法律法规发生变化时，安全管理负责人应组织复核。本制度依据范围包括《中华人民共和国网络安全法》（2025 年 10 月修正、2026 年 1 月 1 日起施行的文本）、《中华人民共和国个人信息保护法》《中华人民共和国数据安全法》《中华人民共和国计算机信息系统安全保护条例》《计算机信息网络国际联网安全保护管理办法》《互联网安全保护技术措施规定》，以及在实际经营活动适用时的《中华人民共和国电子商务法》。具体适用义务取决于运营主体、网络设施位置、服务对象及数据处理活动；《个人信息保护法》也规定了境外处理境内自然人个人信息、并以向境内自然人提供产品或服务为目的等情形的适用范围。网站面向全球用户不当然排除中国或其他国家和地区的强制规定，签署前应完成适用性核对。

**第二条** 本网站向全球用户提供 Desktop2Stereo 软件介绍、购买、下载入口及使用说明；通过电子邮箱账户管理订单、付款状态、软件授权、设备绑定和登录凭据。服务端代码还包含支付回调、余额、邀请奖励及提现审核等业务能力；具体渠道和功能仅在运营方实际启用后适用。

**第三条** 本网站不提供用户向公众发布文字、图片、音视频等内容的功能，不提供用户之间的评论、即时通讯或群组功能。因此，不设置针对用户公开内容的审核岗位或内容传播监控流程。若将来新增公开发布、评论、通讯或社区功能，须先评估并修订本制度及相应技术控制。

**第四条** 本制度适用于账户注册、邮箱验证、登录退出、密码重置、订单和支付、软件下载与授权、设备管理、后台操作、日志保存、个人信息保护、投诉处理、应急响应及监管配合。

**第五条** 本制度须由责任人审核、批准并签署后生效。网站实际功能或适用要求变化时，安全管理负责人应提出修订并留存版本记录。制度文本不得替代系统实际控制、必要的备案许可或主管部门要求。

## 第二章 安全责任与后台权限

**第六条** 本网站指定安全管理负责人一名：［姓名A］；安全管理员一名：［姓名B］。任命书和指定书作为附件单独归档。人员变更时应更新任命文件、权限和交接记录。

**第七条** 安全管理负责人负责统筹本制度执行、批准监管数据调取与导出、决定异常账户处置、组织应急响应、对接主管部门，并复核安全事件和制度执行情况。

**第八条** 安全管理员按授权执行账户和订单核查、日志查询与导出、紧急账户限制、投诉记录和材料归档。安全管理员不得共享管理员凭据，不得超出审批范围查看、导出或修改数据；日志不得由管理员修改或删除。

**第九条** 后台管理员身份与前台用户账户分离。前台账户不得直接用于后台登录。后台登录使用独立管理员凭据、强密码和失败锁定；超级管理员初始化通过受控部署流程完成，不开放公开注册。

**第十条** 后台页面和管理 API 默认要求管理员身份认证。日志查看/导出、账户限制、身份核验、权限管理和留存清理按最小权限分配角色。后台敏感读写操作均须记录操作者、时间、来源 IP、目标对象和执行结果。账号应使用个人专属凭据；具备条件时启用多因素验证。

## 第三章 账户、邮箱和个人信息管理

**第十一条** 用户以电子邮箱注册。账户完成邮箱验证码验证后方可激活；未验证账户不得登录、购买、创建有效授权或取得下载授权。验证码有效期不得超过 15 分钟；发送接口须按邮箱和来源 IP 限速，并使用已启用的反自动化措施。

**第十二条** 系统记录注册时的邮箱、注册时间、来源 IP 和 User-Agent，并保留邮箱验证状态及验证时间。用户完成邮箱验证码后，账户激活状态、注册快照及成功的 `REGISTER` 行为日志须在同一数据库事务中写入；任一写入失败则整体回滚，避免账户激活但缺少对应留痕。注册快照与账户后续修改的邮箱分开保存；如邮箱变更功能开放，应另行记录变更事件，不得改写注册时快照。

**第十三条** 本网站面向全球用户，不以中国手机号或中国身份证作为注册前置条件，不要求用户注册时提交护照或其他证件。因异常交易、争议或安全事件确有必要时，可按个案触发身份核验，并记录核验依据、状态、审核人和时间。证件号码不得以明文持久化；后台目前使用带 `d2s-identity-document-v1` 域分离的 HMAC-SHA-256 摘要，密钥由独立环境变量 `D2S_ID_DOCUMENT_HMAC_KEY` 提供，要求为 32 字节随机值并与数据库分开管理。密钥缺失或格式错误时，核验写操作必须失败关闭；旧版无密钥 SHA-256 摘要不得用于 `VERIFIED` 状态，后台读取旧记录时会经审计事务降为待核验并清除旧摘要。生产启用前仍须完成 Secret 注入、访问控制、密钥备份/轮换流程和部署验收；在确认生产 Secret 配置之前，不得向生产接口录入真实证件号码。证件图片或原件如无必要不得收集或留存。

**第十四条** 个人信息按提供账户、购买、支付、下载和授权服务所必需的范围处理。当前涉及的信息可能包括邮箱、账户标识、注册/登录/购买来源 IP、User-Agent、订单及支付渠道返回的有限关联标识、软件授权和设备摘要。设备指纹、来源端口、服务目标地址或支付账户标识无法从运行环境或渠道可靠取得时，字段保留空值，不得伪造。

**第十五条** 支付账户标识仅保存渠道实际返回且业务确有必要的脱敏值或摘要；不保存完整银行卡号、支付密码、验证码或支付凭证明文。任何第三方支付渠道是否提供可追溯标识，以渠道接口和实际配置为准。

**第十六条** 管理员不得将用户资料、日志、订单或证件核验信息用于本制度目的以外的用途。向外提供数据须经过负责人审批并核对请求主体、法律依据、数据范围和交付方式；应保留审批及交付记录。

## 第四章 用户行为日志与留存

**第十七条** 系统应记录可识别的用户安全及业务行为，包括注册、登录成功与失败、退出、购买、密码重置、账户资料变更、授权相关操作及可识别账户的软件下载行为。每条行为日志至少包括：用户 ID、事件时邮箱快照、操作类型、UTC 事件时间（秒级）、来源 IP/端口、目标 IP/端口、User-Agent、设备指纹哈希、请求路径、结果状态和记录哈希。无法获得的网络字段或设备标识留空；未知账户的失败登录允许 user_id 为空。

**第十八条** 日志不得记录密码、邮箱验证码、访问令牌、刷新令牌、支付密钥、完整支付/Checkout 链接或 URL 查询参数中的敏感值。常规应用诊断日志不得输出用户邮箱明文；用户行为审计仅按规定字段和访问控制留存邮箱快照。User-Agent 和请求路径按规格限制长度并清理敏感参数。登录成功、失败和被安全规则拒绝的结果均须记录；连续失败达到系统阈值时应实施临时锁定或加强验证，并记录锁定/拒绝事件。

**第十九条** 用户行为日志、注册快照、后台操作审计及清理审计默认不自动删除，系统对上述记录统一设置不少于 180 天的内部留存下限。《中华人民共和国网络安全法》第二十三条第三项要求网络运营者留存相关网络日志不少于六个月；本制度要求的用户行为日志中属于该法所称网络日志的记录，应至少留存六个月。该法定义的网络日志范围及本制度其他数据类别的具体法定期限，应由安全管理负责人结合运营主体、系统功能和适用规定逐类确认，不得仅凭本制度推定某类数据全部属于或不属于法定网络日志。其余个人信息保存期限应按实现处理目的所必要的最短时间确定，并向用户如实告知；依法必须留存的个人信息，在法定保存期限未届满期间，按适用法律限制其处理范围，期限届满后依法处置。依法应删除、更正或限制处理的请求，应按适用法律评估并执行。任何审计清理策略的最短天数必须在服务端硬编码为不少于 180 天，低于该值的配置或请求必须被拒绝。

**第二十条** 日志采取仅追加写入。后台和普通用户接口不得提供日志 UPDATE、DELETE、清空或删除表的功能。每条用户行为日志按固定版本的关键字段计算 SHA-256，并提供按日志 ID 重新计算和比对的校验功能。哈希校验用于发现记录变化，不单独构成对数据库管理员或底层存储的防篡改证明；应结合数据库权限、备份和运维审计。

**第二十一条** PostgreSQL/MySQL 生产数据库须为应用运行身份对用户行为日志、注册快照、管理员审计和清理审计表仅授予 INSERT 和 SELECT 权限，不授予 UPDATE、DELETE、TRUNCATE 或列级 UPDATE。审计表建表和升级须使用独立迁移身份，通过目标与 `SQL_DSN` 相同数据库和 schema 的 `D2S_AUDIT_MIGRATION_DSN` 执行 `go run ./cmd/d2s-audit-migrate`；该迁移 DSN 不得注入长期运行的应用服务。受控清理另使用独立身份。仓库提供 `deploy/d2s-audit-permissions.postgresql.sql` 和 `deploy/d2s-audit-permissions.mysql.sql` 授权脚本；迁移完成后由数据库管理员按实际数据库名、schema 和账户执行并核验有效权限。PostgreSQL 脚本还断言无列级 UPDATE、TRUNCATE、REFERENCES 和 TRIGGER，并检查清理身份各表权限范围。MySQL 权限可由全局、数据库、表及角色授权叠加，执行人须检查 `SHOW GRANTS` 和有效角色，确保不存在可覆盖表级限制的宽泛授权。`D2S_AUDIT_CLEANUP_DSN` 应连接同一数据库和 schema，并使用独立清理身份：仅三张留存数据表允许 SELECT/DELETE，清理审计表允许 SELECT/INSERT。SQLite 无法提供表级账户权限，须通过文件访问权限和独立维护流程补足，并如实记录该限制，不得声称已实现数据库账户级授权。

**第二十二条** 受控清理仅允许删除已超过最短留存期限的数据。成功清理须在同一事务中写入清理审计记录并删除目标数据，记录至少包含执行人/任务身份、执行时间、数据表、起止时间范围、删除数量和执行结果；任一步失败均须回滚清理事务，并在新事务中追加 `FAILURE` 清理审计，记录失败阶段、时间范围、实际删除数量（回滚时为 0）和候选记录统计数。清理审计本身不得被同一清理任务删除。当前实现已按该流程记录事务失败；若数据库故障同时阻断失败审计写入，后台还会尝试追加管理员操作失败审计，但数据库不可用时不能保证数据库内存在失败记录。生产启用前仍须验证迁移后的审计表结构、清理账号权限及故障恢复行为。

**第二十三条** 应按时间范围、用户 ID、邮箱、来源 IP 和操作类型查询日志，结果分页展示，授权角色不得隐藏本制度规定的字段。CSV 导出应包含用户行为日志全部字段，使用 UTF-8 编码，并采用 `access_log_YYYYMMDD_HHMMSS.csv` 文件名。注册信息导出至少包括邮箱、注册 IP、注册时间、邮箱验证状态和验证时间。日志、注册、购买和身份记录的查询、哈希校验及导出须按后台审计策略记录操作者、筛选范围、时间和结果。导出须经安全管理负责人事前批准，审批凭证应与导出审计记录关联归档。当前后台已记录导出开始、完成/失败及导出范围，但未内置双人审批门禁；生产启用导出前，须建立并实际执行可追溯的外部审批流程，或先实现技术审批门禁。

**第二十四条** 登录用户通过首页 GitHub Release、夸克网盘或百度网盘入口发起下载时，客户端先调用服务端白名单跟踪路由。服务端校验用户会话、邮箱验证状态及登录限制，并在跳转前追加 `DOWNLOAD` 行为日志；目标值仅允许 `release`、`quark`、`baidu`。日志成功表示下载链接点击已记录，不代表外部文件传输完成。匿名用户仍可使用公开下载直链，该路径不关联账户。当前浏览器/服务端契约无法提供设备指纹时字段留空。

## 第五章 订单、支付和授权关联

**第二十五条** 购买记录须能关联订单编号、用户 ID、邮箱快照、购买时间、产品标识、金额、币种、支付方式、渠道可提供的脱敏/哈希支付账户标识、来源 IP 和结果状态。订单创建时保存的邮箱快照用于同一订单后续 Checkout 和重试；用户之后修改账户邮箱，不得改写订单快照或改变同一订单的支付请求身份参数。金额使用货币最小单位及明确币种保存。订单价格、支付成功状态和授权状态由服务端或已验证的支付回调确定，不信任客户端自行提交的价格或付款结果。

**第二十六条** 支付回调须验证相应支付渠道的原生签名或可信中转签名，并执行幂等处理。订单、支付事件和授权变更应保持可追溯关联。支付渠道未返回账户标识时保留空值，不得阻断合法支付或编造关联信息。

**第二十七条** 账户购买限制、邮箱未验证、订单状态异常或授权安全规则命中时，服务端须拒绝相应购买或授权操作。适用时记录订单/授权操作结果和阻断原因；不得只在前端隐藏购买入口。

**第二十八条** 设备标识仅保存摘要，不保存原始设备指纹。授权签名私钥、支付桥密钥、会话密钥等秘密不得进入制度附件、普通日志、代码仓库或用户可访问数据。

## 第六章 应急处置与账户紧急限制

**第二十九条** 出现批量异常注册、集中登录失败、异常购买/支付、账号被盗、授权滥用、数据泄露或服务受到攻击等情况时，安全管理负责人组织核查和应急处置；必要时由安全管理员协助。

**第三十条** 后台应支持针对单个账户立即禁止登录、禁止购买及撤销现有会话。限制必须在服务端所有相应入口生效，并记录管理员、账户、操作类型、原因、时间、来源 IP 和结果。解除限制使用对应的紧急解除操作并记录审计。

**第三十一条** 对按 IP 段、邮箱域名或注册时间窗口筛选的账户，可执行批量限制。执行前须展示筛选条件与预计影响账户数，进行二次确认；审计记录须保存操作参数、影响数量、操作者和结果。批量处置不得把筛选条件直接当作授权依据，执行人须复核目标范围。

**第三十二条** 应急处置时保全相关日志、订单、支付事件和授权状态，不得覆盖或删除证据。依法需向主管部门报告或提供资料时，由安全管理负责人按适用程序办理，并保留报送、查询和交付记录。事后形成处置时间线、影响范围、恢复措施和改进事项。

**第三十三条** 至少每年进行一次内部应急流程检验，覆盖账户限制、强制下线、日志查询和导出，并记录演练范围、结果、缺陷和整改情况。未验证的演练项目不得记为通过。

## 第七章 投诉与争议处理

**第三十四条** 投诉受理渠道以 d2s.site 当前实际公开的联系页面或运营方正式公布的联系方式为准。若网站尚未提供统一投诉入口，运营方须在启用本条前确定并公布有效渠道；不得在未实际配置时声称网站已有显著展示的投诉举报入口。

**第三十五条** 对账户、付款、订单、下载和授权争议，记录受理时间、关联账户/订单、处理人、处置结果和反馈时间。仅收集处理事项所需的信息；涉及安全事件的记录按本制度留存和访问控制。

## 第八章 监管配合与数据支持

**第三十六条** 安全管理负责人负责接收依法提出的查询、调取和检查要求，核验主体和范围，审批数据查询或导出；安全管理员按审批执行并复核交付内容。提供数据应限定于合法、明确的范围，并记录依据、字段范围、导出人、复核人、时间、方式和结果。

**第三十七条** 监管数据优先使用可读、可核对的通用格式导出。导出文件应安全传递、限制访问，并按要求归档或在目的完成后依批准流程处置。不得通过未授权渠道发送账户密码、验证秘密或支付凭据。

## 第九章 安全运行与复核

**第三十八条** 正式域名为 `d2s.site`。生产环境应使用 HTTPS；反向代理仅信任明确配置的代理地址传入的客户端 IP。数据库、Redis 和内部管理端口不得因便于排障而直接暴露公网。生产配置、证书、备份、访问控制和恢复流程应按部署方案落实并定期复核。

**第三十九条** 生产数据应按运维方案备份并限制备份访问。审计数据备份应与在线业务数据分开控制，定期验证可读性和完整性。访问密钥、签名私钥和支付密钥通过受控 Secret 管理并制定轮换和泄露应急流程。

**第四十条** 安全管理负责人至少每年复核一次网站功能、日志字段、权限、留存、外部渠道和应急流程；出现重大功能变更、安全事件或适用要求变化时应及时复核。本制度的任何条款均不得被解释为系统已经通过尚未执行的部署验收或合规评估。
