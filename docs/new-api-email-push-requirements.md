# New API 后台邮件推送接入要求

## 1. 目标

在 New API 管理后台的“运维”菜单中增加“邮件推送”选项，接入腾讯云 SES（邮件推送）API。以后系统产生的密码重置、邮箱验证、订单、支付、退款、授权和安全通知等邮件，统一通过腾讯云 SES 模板发送。

腾讯云发信域名已经配置并验证完成，系统不负责创建或验证发信域名，只负责读取配置、选择模板、填充变量和调用发送接口。

参考资料：

- [腾讯云 SES API 概览](https://cloud.tencent.com/document/product/1288/51062)
- [腾讯云 SendEmail 接口](https://cloud.tencent.com/document/api/1288/51034)
- [腾讯云邮件推送控制台](https://console.cloud.tencent.com/api/explorer?Product=ses&Version=2020-10-02&Action=CreateEmailIdentity)

## 2. 明确边界

系统不得实现以下功能：

- 创建发信域名；
- 生成 DNS 验证记录；
- SPF、DKIM、MX 验证；
- 修改腾讯云 SES 发信域名；
- 在代码中拼接并直接发送任意 HTML 邮件；
- 在业务代码中直接调用腾讯云 API。

系统只实现：

1. 腾讯云 SES 凭证和发信参数配置；
2. 业务场景到腾讯云 `TemplateID` 的映射；
3. 模板变量校验和组装；
4. 通过 Go `net/http` 调用腾讯云 `SendEmail`；
5. 发送结果、错误信息和 RequestId 记录。

## 3. 后台页面

在 New API 管理后台“运维”菜单增加“邮件推送”页面。

### 3.1 基础配置

- 启用腾讯云邮件推送；
- 腾讯云地域，默认支持 `ap-guangzhou` 和 `ap-hongkong`；
- SecretId；
- SecretKey；
- 默认发件人邮箱；
- 默认发件人名称；
- 默认回复地址；
- API 超时时间；
- 失败重试次数；
- 测试收件邮箱。

SecretKey 必须脱敏保存和展示，不得出现在 API 响应、前端代码、普通日志、错误信息、Git 文件或 Docker 镜像中。数据库保存时应使用项目现有的加密或密钥保护方案。

### 3.2 模板配置

增加业务场景与腾讯云模板的映射配置：

| 业务场景 | TemplateID | 类型 | 必填 |
| --- | ---: | --- | --- |
| 密码重置 | 腾讯云现有模板 | 触发类 | 是 |
| 邮箱验证 | 腾讯云现有模板 | 触发类 | 是 |
| 注册成功通知 | 配置项 | 通知类 | 是 |
| 登录安全通知 | 配置项 | 通知类 | 是 |
| 订单创建通知 | 配置项 | 事务类 | 是 |
| 支付成功通知 | 配置项 | 事务类 | 是 |
| 退款通知 | 配置项 | 事务类 | 是 |
| 拒付通知 | 配置项 | 事务类 | 是 |
| 授权成功通知 | 配置项 | 事务类 | 是 |
| 授权到期提醒 | 配置项 | 通知类 | 是 |
| 系统异常通知 | 配置项 | 通知类 | 是 |
| 测试邮件 | 配置项 | 测试类 | 是 |

密码重置和邮箱验证直接调用腾讯云已经配置好的模板。其他模板必须先在腾讯云 SES 中创建并审核，再把 `TemplateID` 配置到系统中。

页面应显示每个模板的启用状态、TemplateID、业务类型、必填变量、最近测试时间和最近发送结果。TemplateID 不得硬编码在业务代码中。

## 4. 模板内容规范

所有模板必须体现真实、明确的业务场景。除变量以外的固定文字必须能够判断邮件用途、触发原因和处理方式。

同一用户的不同模板业务类型应保持统一：

- 密码重置、邮箱验证：触发类；
- 支付成功、订单状态、退款、授权变更：事务类；
- 登录提醒、系统异常、到期提醒：通知类；
- 产品推广或活动介绍：营销类。

特殊业务类型必须在开发前说明。

### 4.1 字数

- 营销类邮件：固定正文至少 150 字；
- 通知类邮件：固定正文至少 50 字；
- 事务类邮件：固定正文至少 50 字；
- 测试类邮件：固定正文至少 50 字；
- 触发类邮件：无最低字数要求，但必须说明触发原因、验证码或操作步骤。

不得通过大量变量规避固定文字要求。

### 4.2 变量

- 变量与固定文字的比例不得超过 1:5；
- 不允许全变量模板；
- 验证码、订单号、金额、产品名、到期时间等变量必须有明确文字说明；
- 变量名称必须与后端发送参数严格一致；
- 必填变量缺失时，后端必须拒绝发送且不得调用腾讯云 API。

### 4.3 图片和链接

- 单个模板图片不得超过 50 张；
- 不允许全图片模板；
- 不允许只有一张图片而没有文字；
- 图片必须来自稳定、合规、可访问的 HTTPS 地址；
- 链接必须确定、可访问且与邮件业务一致；
- 优先使用项目正式域名，例如 `https://100393.com`；
- 带变量的链接必须固定域名和路径结构，例如 `https://100393.com/account/reset/{{code}}`；
- 不得使用来源不明、随机、短链或无法确认安全性的地址。

### 4.4 禁止内容

模板和实际发送内容不得包含：

- 钓鱼、欺诈或冒充官方；
- 充值、抽奖、彩票、返现、返利、秒杀；
- 色情、毒品、暴力、恐吓；
- 赌博、贷款、催债、刷单；
- 宗教、迷信；
- 引导添加 QQ、微信、微信群或其他社群；
- 代开发票；
- 垃圾邮件、内容不清晰邮件或灰色业务；
- 未经收件人许可的营销邮件；
- 与用户实际操作无关的诱导性内容。

## 5. Go 实现要求

使用 Go 和标准库 `net/http` 调用腾讯云 SES，不使用腾讯云 Go SDK，除非项目现有架构已经统一使用该 SDK。

通过 TC3-HMAC-SHA256 实现腾讯云 API 签名，包括：

- CanonicalRequest；
- RequestTimestamp；
- CredentialScope；
- StringToSign；
- SigningKey；
- Authorization Header。

请求地址：

```text
https://ses.tencentcloudapi.com/
```

公共参数：

```text
Action=SendEmail
Version=2020-10-02
Region
Timestamp
Nonce
```

建议统一抽象：

```go
type TemplateEmailMessage struct {
    Scene        string
    TemplateID   uint64
    To           []string
    Cc           []string
    Bcc          []string
    From         string
    ReplyTo      string
    TemplateData map[string]string
}

type EmailTemplateSender interface {
    SendTemplate(ctx context.Context, message TemplateEmailMessage) error
}
```

建议实现 `TencentSESEmailSender`，业务代码只能调用统一邮件服务，不得直接访问腾讯云 API。

## 6. 业务邮件改造

将现有邮件发送入口统一收敛到模板邮件服务，至少覆盖：

- 注册验证码；
- 登录验证码；
- 密码重置；
- 邮箱验证；
- 登录安全通知；
- 订单创建通知；
- 支付成功通知；
- 退款通知；
- 拒付通知；
- 授权成功通知；
- 授权到期提醒；
- 系统异常或管理员通知。

密码重置和邮箱验证调用腾讯云已有模板，其他场景调用对应的腾讯云模板。禁止业务代码自行拼接 HTML 邮件。

缺少模板、模板未启用、变量缺失、收件人无效或发信配置不完整时，必须在发送前失败并返回明确错误。

## 7. 管理 API

按照项目现有管理员路由风格实现，建议包括：

```text
GET  /api/admin/operation/email
PUT  /api/admin/operation/email
POST /api/admin/operation/email/test-connection
POST /api/admin/operation/email/test-send
GET  /api/admin/operation/email/templates
PUT  /api/admin/operation/email/templates
GET  /api/admin/operation/email/logs
```

要求：

- 所有接口必须进行管理员权限校验；
- SecretKey 永不回显；
- 测试连接只验证凭证和接口连通性，不发送邮件；
- 测试发送必须明确指定模板和测试收件人；
- 发送失败时返回腾讯云错误码和 RequestId，但不得泄露凭证；
- 邮件内容、验证码和 SecretKey 不得写入普通日志。

## 8. 可靠性和安全

必须实现：

- 请求超时；
- 有限重试和指数退避；
- 防止重复发送；
- 发送日志和腾讯云 RequestId；
- 收件人、模板变量和发件人格式校验；
- 发送频率限制；
- 邮件内容和敏感字段脱敏；
- 不允许无限重试；
- 不允许前端直接调用腾讯云 API。

如果项目已有异步任务或队列机制，优先复用，避免邮件发送阻塞注册、登录、支付等主业务请求。

## 9. 测试和验收

### 9.1 单元测试

- TC3 签名计算；
- CanonicalRequest 生成；
- Authorization Header；
- 模板变量校验；
- 配置脱敏；
- 收件人和发件人格式校验；
- 超时、重试和腾讯云错误码转换；
- 模板未配置或变量缺失时禁止发送。

### 9.2 集成测试

使用 HTTP mock server 模拟：

- SendEmail 成功；
- 凭证或签名错误；
- 模板不存在；
- 模板变量缺失；
- 频率超限；
- 网络超时；
- 腾讯云服务端错误。

测试不得使用真实 SecretKey、真实验证码、真实收件人或生产 TemplateID。

### 9.3 最终验收

1. “运维”菜单出现“邮件推送”；
2. 可以配置腾讯云凭证、地域、发件人和 TemplateID；
3. 不提供创建或验证发信域名的功能；
4. 密码重置和邮箱验证直接调用腾讯云现有模板；
5. 其他业务邮件统一使用腾讯云模板；
6. 业务代码不再直接拼接 HTML 邮件；
7. 缺少模板变量时不会调用腾讯云 API；
8. 可以发送指定模板的测试邮件；
9. 可以查看发送结果和 RequestId；
10. SecretKey、验证码和邮件正文不会进入日志；
11. 通过项目现有 Go 测试、`go vet` 和 `git diff --check`；
12. 更新 API 文档、部署文档和模板变量说明；
13. 不提交任何真实凭证、Token、密码、TemplateID 或测试收件地址。

执行前必须先检查现有邮件架构、管理员路由、配置模型和任务队列。若实际结构与本文不同，先报告影响文件和调整方案，再开始修改。
